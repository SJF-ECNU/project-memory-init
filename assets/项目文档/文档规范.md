# 文档规范

本规范约束项目自有文档的放置和关系维护。它不改变代码、配置、OpenSpec 或其他已有变更系统的权威性。

## 内容分流

- 可长期引用的架构、指南、运行手册、参考、决策、计划和验证结果放在项目文档目录。
- 当前目标、最新进展、阻塞和交接信息放在 [[project-memory/首页|Project Memory]]。
- 属于仓库现有变更协议的内容保留在原系统，文档索引只链接，不复制。
- 依赖、生成物和外部同步副本不纳入项目文档图谱。

## 项目分类

| 分类 | 适用内容 | 目录或现有约定 | 分类索引 |
| ---- | -------- | -------------- | -------- |
| 〔仅保留项目实际使用的分类〕 | 〔范围〕 | 〔路径〕 | 〔双链〕 |

每篇文档只进入一个主要分类。跨领域的依赖、补充、验证、替代关系通过双链表达，不在多个索引中复制同一条目。

## 新增与更新

新增、移动或明确替代一篇权威文档时：

1. 选择最接近的已有分类；单篇文档不为自己新建一层目录。
2. 更新对应分类索引，注明它是当前有效、草稿或计划、已替代还是历史资料。
3. 只有关系能帮助理解或追溯时，才在相关文档中增加“相关文档”链接。
4. 已替代文档继续保留历史入口，并明确链接替代它的文档。
5. 如果改动路径，同步更新全部引用并运行链接检查。

## 处理已有文档

旧路径默认保留，先通过 [[docs/首页|文档首页]] 和分类索引建立结构。重复、冲突、孤立或状态不明的文档列入待核对；未确认前不删除、不合并，也不把历史文字改写成当前事实。

只有在确认文档归属、新位置、全部引用和用户规则后才移动旧文档。仓库已有清晰约定时沿用原结构，不为匹配模板而重排。

## 状态与元数据

索引中的状态说明是最低要求。仓库已使用 frontmatter 时沿用现有字段；没有统一元数据时，不批量修改旧文档，只在新建或实质更新的文档中按需使用：

- `type`：文档类型；
- `status`：`current`、`draft`、`superseded` 或 `historical`；
- `updated_at`：本次内容核对时间。

文件名或修改时间不能单独证明文档当前有效，权威性仍需根据代码、配置和采用记录核对。
