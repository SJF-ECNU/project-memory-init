# 项目记忆初始化规范

本规范在 `project-memory-init` 写入目标仓库前完整阅读。目标是生成“足够接管、不过度复制、不会冒充实时状态”的项目记忆。

## 来源调查

根据项目实际存在的内容调查，不要求所有类别都有文件。

| 类别       | 常见来源                                                              | 必须提取的事实                                              |
| ---------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| 智能体规则 | `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.github/copilot-instructions.md`、厂商规则目录 | 修改流程、工具要求、禁止事项、内容分流、文档同步规则、作用域 |
| 产品背景   | README、产品说明、架构文档、路线图                                    | 项目解决什么问题、主要用户/场景、当前产品面、非目标         |
| 文档关系   | 文档首页、目录、索引、标题、首段、链接和状态说明                      | 主题分类、权威入口、重复冲突、替代关系、孤立与排除范围      |
| 代码结构   | CodeGraph、workspace 清单、包清单、目录、入口源码                     | 主要模块、职责、语言/运行时、关键边界                       |
| 当前变更   | Git、OpenSpec、Issue/计划目录、迁移                                   | 当前分支、未提交工作、进行中目标、最近已验证状态            |
| 本地开发   | package scripts、Makefile、Compose、环境示例、测试配置                | 启动、构建、测试、端口、依赖和数据位置                      |
| 部署运维   | Runbook、Compose/Kubernetes/IaC、CI/CD、发布脚本                      | 环境名称、主机/集群、服务角色、网络入口、构建/发布/回滚路径 |
| 安全与数据 | 安全文档、权限配置、存储/备份、秘密管理                               | 权限边界、敏感信息位置、不可逆操作、备份与恢复约束          |

完整阅读根级智能体规则；代码和文档只深入到能满足交付物的程度。不要为了“完整”逐行阅读整个代码库。

## 事实优先级

发生矛盾时按以下顺序判断，并在项目背景或环境部署中记录冲突：

1. 当前命令结果、Git、代码和配置。
2. 当前变更规范、已接受设计和可执行脚本。
3. 持续维护的架构、运维和仓库说明。
4. 项目记忆摘要与历史工作记录。

“文档登记的生产地址”不是“当前在线”，“存在发布脚本”不是“已授权发布”，“历史测试通过”不是“当前生产批准”。

## 必需交付物

### 首页

保持短小，只提供接管顺序、权威导航和工作流列表。接管时默认读取相关工作流最近一篇记录；当信息不足以解释当前状态、决策、阻塞、依赖或代码差异时，允许智能体按时间由近到远主动追溯相关历史，信息足够后停止。明确仓库根是 Obsidian Vault，并提供 `path:"project-memory/" -path:"project-memory/模板/"` 全局图谱筛选提示，使图谱聚焦背景、工作流和工作记录，而不是普通 README 与依赖文档。默认不创建或覆盖用户的 `.obsidian/` 配置。

### 项目概览

提供一句话定位、主要目录/模块表、架构锚点和深入阅读入口。容易过期的分支、版本和实时状态标明观察时间或改为动态检查指引。

### 项目文档关系层

完整遵循 [项目文档结构化规范](文档结构化规范.md)。在已有文档结构之上创建或补齐一个轻量关系层，使 `docs/首页.md` 连接实际存在的分类索引，再由分类索引连接具体文档。项目使用其他文档根时沿用其现有路径。

旧文档默认保留原路径和正文。初始化应显式列出重复、冲突、孤立、疑似过期和状态未知项，但不得仅凭文件名或修改时间擅自合并、删除或宣称某篇文档已经失效。只有能够更新全部引用且不存在权威性歧义时才移动文件。

### 项目背景与当前边界

至少覆盖：

- 项目目标、主要用户或场景；
- 产品面和主要子系统；
- 当前已经具备的关键能力；
- 明确未实现、非目标或不能宣称的能力；
- 主要领域/执行/数据边界；
- 已知来源冲突和采用依据；
- 权威阅读地图。

### 开发与运维注意事项

只提炼会改变智能体决策的高影响规则：修改前置流程、代码/文档一致性、事实与敏感数据边界、权限和生命周期、测试证据边界、生产红线和按任务深入阅读入口。避免复制所有代码风格细节。

### 环境与部署

项目没有生产环境时明确写“仓库未登记生产环境”，不能编造。存在部署资料时至少覆盖：

- 本地、测试、预发布、生产等环境及用途；
- 文档登记的主机、集群、区域和公网入口；
- 长期服务、一次性 Job、临时 Runtime 的职责、端口和权限边界；
- 固定路径、持久卷、对象存储和外部依赖；
- 构建发生在哪里、部署目标在哪里；
- 发布前提、验收、回滚和销毁禁令；
- 哪些只是静态文档状态，哪些经过本次实时核验。

### 协议、模板和日常 Skill

协议定义事实优先级、记录触发、接管、事实刷新、收尾、元数据、链接和敏感信息边界。工作流是可变状态，只保留当前仍相关的权威文档；工作记录只追加，并区分实质影响本次工作的“参考文档”和本次所有新建、更新、移动或明确替代的“文档产物”。日常 Skill 只把智能体引导到协议，不复制整个项目背景。

### 智能体入口与内容分流

完整遵循 [智能体入口兼容](智能体入口兼容.md)。根 `AGENTS.md` 是不同智能体共享的稳定规范源，必须包含短小的 Project Memory 入口和以下分流原则：

- `AGENTS.md` 及厂商入口文件只保存稳定、跨大多数任务、会改变智能体行为且无法通过短指针低成本恢复的规则。
- 代码、配置、架构、运行手册和变更规范保存详细行为与操作程序，并保持各自的权威性；新增、移动或替代项目文档时遵循仓库内的文档规范并更新对应索引。
- 项目记忆稳定笔记保存足以接管的项目内容、当前边界、开发注意事项与环境部署摘要，并链接权威来源。
- 工作流保存当前目标、已验证进展、阻塞和下一步；工作记录保存只追加的完成、阻塞、取消或移交证据。
- 工作记录通过有语义的双链连接参考文档和文档产物；文档侧依靠 Obsidian 反向链接追溯工作历史，不为回链复制日志。
- 普通问答和没有形成持久结论的探索不写入任何记忆。

使用 `assets/智能体入口/` 生成 `AGENTS.md` 内容片段以及 Claude、Gemini、Copilot 薄入口。其他原生读取 `AGENTS.md` 的工具直接复用该文件，不复制完整规则。

## 保留式更新

发现现有项目记忆时先做文件矩阵：`存在且完整`、`存在但缺项`、`冲突`、`缺失`。采用以下动作：

- 完整：保留，只更新确实变化的持久事实或链接。
- 缺项：在原有组织下补齐，不为套模板重写全文。
- 冲突：记录冲突与采用依据；无法安全决定时请求用户选择。
- 缺失：从资产模板创建。

工作记录不回写；工作流不因初始化重跑而重置。已有 `AGENTS.md` 和厂商入口文件按 [智能体入口兼容](智能体入口兼容.md) 保留式补齐，不删除、重排或翻译其他规则。已有项目文档先加入关系索引，默认不移动或重写；文档首页和分类索引已经存在时在原结构内补齐，不另建竞争入口。

## 安全边界

可以记录仓库文档已经公开的非敏感 IP、域名、端口、服务名、云区域、固定路径和发布命令名称。不得记录：

- API Key、AccessKey、Token、Cookie、密码、私钥或密钥值；
- 完整 `.env`、生产数据库 URL、敏感请求/响应、provider body；
- 用户文件、私有 Artifact、模型上下文或原始命令输出；
- 无法从来源验证的服务器、角色、版本、模型或会话标识。

## 接管验收问题

初始化只有在另一位智能体无需原对话即可回答以下问题时完成：

1. 项目解决什么问题，当前主要产品面和模块是什么？
2. 当前已经实现什么，哪些明确没有实现或不能宣称？
3. 修改代码前必须遵守什么流程和高影响边界？
4. 本地如何启动、构建和测试？
5. 是否存在生产环境；若存在，目标、入口、服务角色和发布路径是什么？
6. 哪些状态经过本次核验，哪些只是文档登记或未知？
7. 当前工作流的目标、结果、阻塞和唯一明确下一步是什么？
8. 深入核对每项结论应打开哪个权威来源？
9. 从文档首页如何找到某个主题的当前权威文档、相关计划、验证报告和历史替代关系？
10. 某篇文档被哪些工作参考或修改过；某次工作参考了什么、又产生了哪些文档？
