# 项目记忆

使用仓库内统一的 `project-memory/协议.md`，不创建第二套日志格式。

## 前置条件

确认 `project-memory/首页.md`、`project-memory/协议.md` 与 `docs/首页.md` 存在。核心入口缺失时，使用用户级 `project-memory-init` Skill 做保留式修复。

## 接管

1. 完整阅读 `project-memory/协议.md`，从 `project-memory/首页.md` 进入。
2. 按任务阅读项目概览、背景/边界、注意事项、环境部署和相关文档索引，再选择工作流与最近一篇工作记录；仅在信息不足时从新到旧追溯至多五篇相关记录。
3. 用当前 Git、当前代码/配置和适用 OpenSpec 核对继承状态。切换 checkout 后必须重新读取当前 checkout 的项目记忆和文档图谱。
4. 实现前明确目标、当前证据、阻塞、下一步和任何矛盾。

## 持久事实刷新

当项目规则、架构、配置、发布方式、环境拓扑或文档关系实质变化时：

1. 完整阅读受影响的智能体规则、OpenSpec 与权威来源。
2. 用当前 Git、代码、配置和可执行脚本核对历史文字。
3. 先更新权威来源和对应 `docs/` 索引，再更新项目记忆中足以接管的摘要、冲突和链接。
4. 静态文档、历史测试和构建不能写成实时健康、已安装状态或发布授权；未知项必须明确写未知。

## 收尾

1. 按协议和 `project-memory/模板/工作记录模板.md` 创建只追加工作记录。
2. 只更新受影响工作流，记录真实智能体/模型/Git 元数据、验证、剩余工作和明确下一步。
3. 检查链接、敏感信息和完成声明。另一位参与者无需原对话即可继续时才算完成。

普通问答或没有形成持久结论的探索不创建工作记录。
