# 环境与部署

本页只记录可接管的非敏感环境事实。操作任何 Vault 或外部目标前，仍须核对实时状态、备份和授权。

## 环境总览

| 环境 | 入口/位置 | 用途 | 本次核验状态 |
| --- | --- | --- | --- |
| 本地开发 | `obsidian-memory-constellation/` | 插件源码、测试与生产构建 | 已核验：仓库清单与脚本 |
| 目标 Obsidian Vault | 用户指定的 Vault `.obsidian/plugins/memory-constellation/` | 手动安装插件产物与前台验收 | 未在本次初始化中操作 |
| 生产/托管 | 仓库未登记 | 不适用 | 未登记 |

## 本地开发

- 前提：README 记录 Node.js 22 或更高版本与 npm。
- 依赖安装：在 `obsidian-memory-constellation/` 运行 `npm ci`。
- 测试：`npm test`。
- 类型检查：`npm run check`。
- 生产构建：`npm run build`。
- 默认服务端口、数据库、后台进程和外部服务：仓库未登记；插件作为 Obsidian 客户端扩展运行。

## 独立桌面端开发

- 工程入口：`desktop/`，Vue + Vite 渲染层、Electron 主进程与 preload。
- 运行、依赖、测试与边界以 [桌面端 README](../desktop/README.md) 为准。
- `npm run build` 后 `npm start` 运行本地源码版；`npm run dev` 仅使用本机 5173 端口。
- userData 中只保存选过的项目目录，浏览不写入项目；显式初始化会调用已安装并登录的 Claude/Codex 写入项目文档。尚未发布安装包，不依赖目标 Vault。

- Claude 转发运行在独立 CC Switch 进程，CLI 环境代理不会替其配置出站网络；本机转发故障的修复证据见 [[project-memory/工作记录/2026/09/初始化CLI兼容与转发修复]]。Codex 的本次模型选择不改变全局 CLI 配置。

## 生产或托管环境

| 字段 | 文档登记值 |

## 服务角色

| 角色 | 网络/端口 | 职责 | 权限与秘密边界 |
| --- | --- | --- | --- |
| Obsidian 插件 | 不适用 | 读取当前 Vault 的文件、frontmatter 与解析链接，展示关系视图 | 只读笔记关系；不应写入、移动、重命名或删除 Vault 文件 |

## 固定路径、存储和外部系统

| 项目 | 用途 | 约束 |
| --- | --- | --- |
| `obsidian-memory-constellation/` | 插件源码与构建工程 | `node_modules/` 和生成的 `main.js` 不提交 |
| 目标 Vault 插件目录 | 保存安装后的 `main.js`、`manifest.json` 和 `styles.css` | 覆盖前备份现有三项文件；目标路径和授权须由操作者确认 |

## 发布、验收与回滚

1. 目标 Vault、现有插件版本、备份与操作授权须在操作前确认。
2. 按 [插件 README](../obsidian-memory-constellation/README.md) 构建，复制三项安装产物后在 Obsidian 启用或重载插件。
3. 用目标 Vault 的直接 UI 观察验收所改交互；不要以构建、测试或静态截图代替动态前台验收。
4. 回滚依赖预先备份的三项插件文件；仓库未登记自动发布或远端回滚程序。

## 接管前必须确认

1. 当前 checkout、插件版本和工作区是否与记录一致？
2. 目标 Vault 是否正确、可访问且已有可恢复备份？
3. 本次改动是否会覆盖插件文件或改变用户 Vault 设置？
4. 需要的构建、安装和前台验收是否都有独立直接证据？
