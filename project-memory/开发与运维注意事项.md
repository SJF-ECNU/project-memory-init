# 开发与运维注意事项

本页只记录会改变智能体决策的高影响规则；具体行为以源码、OpenSpec 和安装说明为准。

## 开始修改前

1. 从 [[project-memory/首页|项目记忆首页]] 接管，并用当前 Git、工作区、源码和 `openspec/` 核对状态；切换 checkout 后不得继续依赖旧分支缓存。
2. 修改插件行为前阅读对应 OpenSpec 提案、设计、任务与规格；变更在其范围内时同步更新需要的 OpenSpec 产物。
3. 新建、移动或明确替代长期项目文档前遵循 [[docs/文档规范|文档规范]]，更新分类索引；当前进度和交接只写入 `project-memory/`。

## 架构与数据边界

- 独立 `desktop/` 的范围见 [桌面端设计](../openspec/changes/add-project-desktop/design.md)。渲染层不直接访问文件系统，浏览不写文件，编辑保存由主进程校验项目、路径、文本类型与磁盘原文后写入；初始化由主进程启动本机 Claude/Codex，仅对选中项目执行。复用根初始化资产，保留 CLI 登录，Claude 沿用默认模型，Codex 可选择本次模型，失败或取消不自动回滚已有文件。结果检查仅验证核心文件存在且非空，不证明内容质量。详见 [初始化设计](../openspec/changes/add-agent-project-initialization/design.md)；修改后运行 `npm test`、`npm run build` 和 `npm run test:ui`。

- 插件对 Vault 内容保持只读，只通过 Obsidian 文件列表、frontmatter 与链接缓存构建模型；任何会写入笔记、改名、移动、删除或引入数据库/后端的提议都超出当前边界。
- 不把凭据、Token、Cookie、密码、私钥、完整环境文件、敏感报文或原始命令输出写入项目记忆、工作记录或文档索引。
- 当前分支只提交源码、规范和说明；`node_modules/` 与生成的 `main.js` 不进入 Git。

## 测试与证据边界

- 修改插件后，按改动运行 `npm test`、`npm run check`、`npm run build`，并运行适用的 `openspec validate --strict` 与 `git diff --check`。
- 构建和测试证明当前 checkout 的工程检查通过；安装到目标 Vault、插件启用状态和前台 Obsidian 视觉/交互验收必须以各自的直接证据单独记录。

## 生产与不可逆操作

- 仓库未登记生产环境或自动发布路径。复制构建产物到用户 Vault、覆盖现有插件文件、启用插件、发布远端分支或创建 Release 都是外部状态改变，应先确认目标与授权。
- 未经明确请求，不删除 Vault 笔记、重置 Git、覆盖用户设置或修改 `.obsidian/` 工作区、主题和插件偏好。
